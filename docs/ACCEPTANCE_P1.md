## 3. 端到端验证（`.smoke-test/verify-api.ps1`）

对**真实进程 + 真实 HTTP + 真实 SQLite** 跑 48 项检查，全部通过：

* 守卫：无令牌 401；JSON 响应声明 `charset=utf-8`；
* 记账：201 创建、方向自动为 `out`、余额变为 `-3500`、响应回带分类名；
* 校验：支出用收入分类 → 422、浮点金额 → 422、分账之和不符 → 422（含差额）、
  转账缺目标 → 422、未知字段 → 422、不存在的账户 → 404；
* 口径：转账后净值不变、本月支出不含转账、本月笔数不含转账；
* 检索：按商户搜索、按类型/账户/分类/金额筛选（重复参数与逗号分隔都支持）、
  分页返回真实总数；
* 日历：区间内每一天都占位（含未记账的日子）；
* 软删除：删除后余额回补、统计归零、恢复后复原；
* 分类：物化路径正确、同级重名 409、内置分类可隐藏但删除 409、合并迁移流水与分账；
* 其它：标签重名 409、账本主人唯一、数据体检通过。

## 5. 缺陷修复记录

本轮修掉的问题（全部是**真实运行才会暴露**、单元测试不易覆盖的类型）：

| # | 问题 | 症状 | 修复 |
|---|---|---|---|
| 1 | `Category(**fields, sort_order=…)` 重复传参 | 新建分类 500 | 改为先 `pop` 再显式传 |
| 2 | JSON 响应未声明 charset | PowerShell 5.1 按 Latin-1 解码，中文全乱、"按分类名查找"全部落空 | 统一 `U8JSONResponse`（`application/json; charset=utf-8`） |
| 3 | 请求模型静默忽略未知字段 | 打错字段名 → "请求成功但改动没发生" | `extra="forbid"`，未知字段一律 422 |
| 4 | 多值筛选只认重复参数 | `?types=a,b` 被当成单值 → "筛什么都没结果"且不报错 | 两种写法都接受 |
| 5 | 分账整体替换时只删数据库 | 内存集合仍持有旧对象，界面显示"删了但还在" | 清空关系集合（配合 delete-orphan） |
| 6 | 同一索引声明两次 | 不报错，只是每次写入白慢一点 | 删除冗余声明并重新生成迁移 |
| 7 | `alembic.ini` 含中文 | configparser 按 GBK 读取 → `UnicodeDecodeError` | 该文件保持纯 ASCII |
| 8 | 迁移脚本未打包 | 打包版启动报 `Path doesn't exist: .../db/migrations` | spec 中把整个 migrations 目录作为数据打包 |
| 9 | 流水列表默认区间为「本月」 | 每月 1 日打开时列表看起来空空如也，用户以为数据丢了 | 默认改为「近 30 天」 |

### 验证脚本自身踩到的三个 PowerShell 陷阱（已写入脚本注释）

| 陷阱 | 症状 |
|---|---|
| 无 BOM 的 UTF-8 `.ps1` 被 Windows PowerShell 按 GBK 解析 | 中文串破损，报出一堆无关的语法错误 |
| URL 里多拼一个 `?` | 令牌进不去查询参数，一片 401 |
| `` `t `` 是**制表符**转义 | URL 变成 `?<TAB>oken=`，退出码 0 但没有截图 |
