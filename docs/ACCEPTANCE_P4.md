# P4 验收：存钱罐与储蓄目标

对应需求 16。本文只写**可验证的判据**，以及几个"看起来可以合并、
实际不能"的设计取舍。

## 2. 可验证判据

### 2.1 余额与进出

* 罐子余额 = `SUM(piggy_bank_deposits.amount_minor)`，**任何时刻都不落库**。
* 取出**允许取空但不容许取成负数**；超出时返回 409 并**带上当前余额**，
  界面才能提示"你只有 50"。
* 删除一笔记录时，判据是"删掉之后余额还剩多少"，**不是金额的正负**。
  > 这里犯过一次真实的错：最初按 `amount_minor < 0`（"取出"）来拦，
  > 方向正好反了 —— 真正会把余额弄成负数的是删掉一笔**存入**。
* 新建罐子可以带 `initial_minor`，它会作为一条存入记录出现（用户看得到它怎么来的）。

### 2.2 里程碑与达成

* 里程碑取值为 25 / 50 / 75 / 100，按 `ratio = 余额 ÷ 目标` 判定。
* `ratio` **不夹到 1**：攒超了要看得出来。
* 达成后**取走一部分，状态保持"已达成"**：攒到过就是攒到过，
  改回"进行中"会让庆祝与历史记录都失去意义。
* 结清用一笔负数 `settle` 记录，**不删存入历史**。
* 生成流水的金额 = **罐子余额**而不是目标金额（账实相符优先于数字好看）。
* 结清可以不生成流水（`create_transaction=False`）：钱可能早就花掉了。

### 2.3 预计达成日（双口径）

线性：`余额 ÷ 已过天数`。加权：近 90 天逐日净存入按 **15 天半衰期**的指数加权。
两个口径**都返回**，并给出 `divergent`（差距超过一倍）。

> 为什么都给：线性稳定但对"最近停止存钱了"**完全无感**；
> 加权敏感但会被一次性大额拉飞。挑一个藏起另一个，等于替用户做了
> 他没授权的假设。**那个分歧本身是有用的信息**（说明攒钱节奏在变）。
>
> 验收用例里有一条专门构造"攒了 90 天、最近 60 天一分没存"，
> 只有加权口径能识别出来。

其它约定：

* 零存入时两个口径都是 `null`，**不给出"还要 0 天"这种看起来像在催的数字**。
* 已达成时提前返回，不计算剩余天数。
* 有期限时给出 `on_track` 与 `required_per_day_minor`。

### 2.4 归集规则

* **四舍五入只作用于支出**（收入凑整没有语义），且正好是整倍数时存 **0**
  —— 存一个 `unit` 会凭空多一笔；用户看到"买 100 元的东西罐子多了 1 元"
  会认为算错了。
* **幂等由数据结构保证**，不靠调用方自觉：
  * 时间驱动靠 `piggy_bank_rules.last_run_date`（应用一天可能被开关很多次）；
  * 事件驱动靠 `(piggy_bank_id, transaction_id, kind)` 唯一性
    （编辑流水后重算会再次走到那里）。
  > "多攒了一笔"用户很难发现 —— 罐子里多几块钱不会引起注意。
* `monthly_surplus` 在当月**赤字时不归集**（负着存会让余额变成负数）。
* `deduct_from_account` 必须同时给出 `account_id`：否则归集成功但钱没少，
  用户对不上账且很难想到是配置缺了一项。
* 一个罐子最多一条规则。

### 2.5 储蓄目标

* 进度 = 关联账户的**实时余额** + 手工注入之和，**都不落库**。
* 账户余额为负时**照实计入**，不夹到 0：
  夹掉会让"我把首付账户刷爆了"看起来跟"一分没存"一样。
* **展示用的 `status` 按当前进度推导**（120% 的目标不该显示"进行中"），
  但**不落库** —— 读操作不该写数据库。暂停 / 放弃是用户的明确决定，推导不覆盖。
  > 这条是**看截图**发现的：进度环写着 120%，却没有达成标记。
* 手工注入与关联账户并存时，界面给出**重复计算警告**。

### 2.6 零数据

没有存钱罐 / 没有目标 / 没有规则到期时，接口返回空数组与 0 合计，
界面给出可操作的引导（"建一个罐子…"），而不是报错或空白。

## 4. 本文档记录的两个真实缺陷（都由验证抓到）

1. **`delete_deposit` 的守卫方向反了**（用例抓到，见 2.1）。
2. **达成态的罐子不是罐子**：100% 的液体铺满罐身，`stroke-separator`
   的轮廓被绿色吞掉，看起来就是一块实心圆角矩形；达成标记是
   `fill-positive/90`，绿底绿勾等于看不见。
   > 这条**只有截图能发现** —— 类型检查、lint、单元测试、构建全都通过。
   > 结论：**可视化的功能必须以截图验收收尾。**
